I.
К Р А Т К О Е   З А Д А Н И Е:
Я хочу построить универсальную систему отчетности. Будет backend и frontend. 
Backend будет многомодульным на java 21. 
Frontend на vue. К сведению vue я не знаю .. поэтому сначала нужно будет делать все примитивно. 
Начнем работу с подготовки backend стороны. 
Что должна делать система. 
Система должна представлять из себя два конструктора. 1. Конструктор для входящих принимающих отчетов 2. Конструктор для исходящих отчетов. 
1. Конструктор входящих отчетов должен позволять рисовать пользователю с "определенными правами" (пока это опустим) входящий отчет, то есть метадату (без банных).
после того как будет нарисован входящий отчет система после установления активности нового входящего отчета, должна уже принимать этот вид отчета.

2. Конструктор исходящих отчетов должен позволять рисовать пользователю с "определенными правами" (пока это опустим) любое количество исходящих отчетов которые будут формировать из входящих отчетов, то есть метадату исходящего отчета (без данных).
после того как будет нарисован входящий отчет система после установления активности нового входящего отчета, должна уже принимать этот вид отчета.

Сначала нужно спроектировать ER модель для реализации входящих отчетов. У меня есть в этом плане некоторые наработки, которые я хотел бы Вам показать. Как мне их Вам показать в каком формате?

Главная цель создать универсальную ER модель в которой можно будет рисовать входящие отчеты любой формы, обычные группированные и т.п.
Так как задача очень сложная решено создать конкретные заполненные формы отчетов в виде Excel с номерами 1, 2 и т.п. и рисовать ER модель.
Следующий шаг будет создать в БД все таблицы, заполнить таблицы и сделать запрос select чтобы можно было входные данные смотреть "представлять" аналогично форме excel.
Будут представлены все excel таблицы для полноты.

В названиях таблиц я использую префиксы:
  - "DR_..." - справочники
  - "MD_..." - мета данные

1.
DR_type_period - таблица в которой храниться типы периодов  отчеты (квартальный, месячный), можно будет создавать любое количество типов периодов, например недельный, или ежедневный

  code_type_period - трехсимвольный код периода, например QUA-квартал, MON-месячный (поле уникальное)
  name_type_period - имя периода, квартал, месяц
